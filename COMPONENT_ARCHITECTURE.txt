COMPONENT ARCHITECTURE - HOW IT WORKS
======================================

BEFORE (Problems):
------------------
❌ Hardcoded navbars in each HTML file
❌ Topbar appearing below navbar
❌ Missing footers on some pages
❌ Inconsistent search functionality
❌ Hard to maintain (update 20+ files for one change)

AFTER (Solution):
-----------------
✅ Component-based architecture
✅ Topbar always above navbar
✅ Footer on every page
✅ Search works everywhere
✅ Update once, applies to all pages

COMPONENT STRUCTURE:
--------------------

┌─────────────────────────────────────┐
│  Company Topbar (order: -2)         │  ← "Delivery across Ghana"
│  Loaded by: company-topbar-loader.js│
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│  Main Navbar (order: -1)            │  ← Logo, Search, Cart, Links
│  Loaded by: navbar-loader.js        │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│  Page Content (order: 0)            │  ← Dashboard, Products, etc.
│  Static HTML in each page           │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│  Footer (order: 998)                │  ← Links, Newsletter, Contact
│  Loaded by: footer-loader.js        │
└─────────────────────────────────────┘
           ↓
┌─────────────────────────────────────┐
│  Mobile Nav (order: 999)            │  ← Bottom navigation bar
│  Static HTML in each page           │
└─────────────────────────────────────┘

LOADING SEQUENCE:
-----------------

Step 1: HTML loads
  └─> <script src="company-topbar-loader.js">

Step 2: Topbar loader executes
  └─> Fetches ../components/company-topbar.html
  └─> Inserts at body start
  └─> Dispatches 'topbarLoaded' event

Step 3: Navbar loader executes
  └─> Waits for 'topbarLoaded' event
  └─> Fetches ../components/navbar.html
  └─> Inserts after topbar
  └─> Dispatches 'navbarLoaded' event

Step 4: Footer loader executes
  └─> Fetches ../components/footer.html
  └─> Inserts before mobile nav
  └─> Dispatches 'footerLoaded' event

Step 5: CSS applies flexbox ordering
  └─> Ensures visual order is correct
  └─> Topbar → Navbar → Content → Footer → Mobile Nav

COMPONENT FILES:
----------------

Source Components (Single Source of Truth):
  frontend/components/company-topbar.html
  frontend/components/navbar.html
  frontend/components/footer.html

Loader Scripts:
  frontend/js/company-topbar-loader.js
  frontend/js/navbar-loader.js
  frontend/js/footer-loader.js

Styling:
  frontend/css/component-order-fix.css

HOW TO USE IN NEW PAGES:
-------------------------

1. Add CSS in <head>:
   <link rel="stylesheet" href="../css/component-order-fix.css">

2. Add loaders before other scripts:
   <script src="../js/company-topbar-loader.js"></script>
   <script src="../js/navbar-loader.js"></script>
   <script src="../js/footer-loader.js"></script>

3. Don't hardcode navbar/footer in HTML
   Just add your page content!

BENEFITS OF THIS ARCHITECTURE:
-------------------------------

1. MAINTAINABILITY
   - Change navbar once → updates everywhere
   - No need to edit 20+ HTML files

2. CONSISTENCY
   - Same navbar/footer on every page
   - Same search functionality everywhere

3. PERFORMANCE
   - Components cached by browser
   - Faster subsequent page loads

4. SCALABILITY
   - Easy to add new pages
   - Just include the loaders

5. DEBUGGING
   - Single source of truth
   - Easier to find and fix issues

6. PROFESSIONAL
   - Modern component-based architecture
   - Industry best practice

This is the same pattern used by modern frameworks like React, Vue, and Angular,
but implemented with vanilla JavaScript for maximum compatibility!
